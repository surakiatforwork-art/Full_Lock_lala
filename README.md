# Full Lock Android

แอป Android แบบ native ที่ย้ายตัวกรองจาก Automagic มาเป็นแอปแยก ใช้ Java 17, Android SDK 35, Gradle wrapper 8.11.1 และ AGP 8.9.1 รองรับ Android 8 ขึ้นไป

## รุ่น 0.1.2

ประวัติแสดงสถานะ “ทำงาน · ส่งคำสั่งเปิดแล้ว” หรือ “ไม่ทำงาน · ไม่ส่งคำสั่งเปิด” พร้อมเหตุผลทั้งหมดที่ไม่ผ่าน เช่น ราคาตามสูตรต่ำกว่าขั้นต่ำ/สูงกว่าขั้นสูง พร้อมตัวเลข พื้นที่และประเภทงานที่ไม่ตรง หรือเวลาพักเปิดซ้อนที่เหลือ สถานะหมายถึงการส่งคำสั่ง ไม่ใช่ยืนยันว่าหน้างานเปิดสำเร็จ ประวัติรุ่นเก่าแสดงผลเดิมโดยไม่คาดเดาสถานะใหม่

- หน้าตั้งค่าภาษาไทย โทนส้มและการ์ดขาวอ้างอิงภาพผู้ใช้
- เมนูตรวจการทำงานแสดงรุ่นเครื่อง/Android สิทธิ์ สถานะเชื่อมต่อตัวอ่าน เวลารับแจ้งเตือน Lalamove ล่าสุด และคัดลอกข้อมูลได้ พร้อมปุ่มขอเชื่อมต่อตัวอ่านอีกครั้ง
- เมนูซ้ายสำหรับสิทธิ์อ่านแจ้งเตือน แจ้งเตือนผล แสดงเหนือแอปอื่น และหน้าข้อมูลแอป/แบตเตอรี่
- ตัวกรองช่วงราคา สูตรหักค่าธรรมเนียม พื้นที่ ประเภทเวลา และรายการราคาบล็อกงานเหมาตาม flow เดิม
- อ่านเฉพาะ `com.lalamove.global.driver.sea` ข้ามแจ้งเตือนสรุปกลุ่ม ป้องกันข้อความเดิมซ้ำใน key เดิม และพักการเปิดซ้อนตามเวลาที่กำหนด
- เรียก `contentIntent` ของแจ้งเตือนโดยตรง ไม่ดึงแถบ ไม่ลบแจ้งเตือน และไม่ปัดรับงานแทนผู้ใช้
- เก็บผลตรวจล่าสุด 30 รายการบนเครื่อง ไม่มีอินเทอร์เน็ตหรือระบบ Login/License ภายนอก

## ติดตั้งและใช้งาน

Build ด้วย `./gradlew.bat :app:assembleDebug :app:lintDebug` และติดตั้ง `app/build/outputs/apk/debug/app-debug.apk` ซึ่งลงชื่อด้วย debug key เหมาะสำหรับทดสอบ

เปิดเมนู ☰ แล้วอนุญาตอ่านแจ้งเตือนให้ Full Lock, อนุญาตแจ้งเตือนของ Full Lock สำหรับปุ่มเปิดงานสำรอง จากนั้นตั้งตัวกรองและกดเริ่มทำงาน บางเครื่องอาจต้องอนุญาต restricted settings ในข้อมูลแอปก่อนเปิด notification access หากติดตั้ง APK เอง

## ข้อจำกัดที่ต้องทดสอบจริง

รองรับหัวข้อ `[หมวด] ต้นทาง > ปลายทาง` และข้อความที่มี `ขนส่งทันที` หรือ `งานล่วงหน้า` พร้อมจำนวนเงินเดียว เช่น `฿156.00` หรือราคางานบวกทิป เช่น `฿276.00 + ฿10.00` ตามภาพที่ผู้ใช้ยืนยัน สูตรหักค่าธรรมเนียมหักเฉพาะราคางานแล้วจึงบวกทิป รูปแบบหลายจำนวนอื่นที่ไม่ใช่สองจำนวนคั่นด้วย + จะไม่เปิด

Android อาจบล็อกการเปิด activity จากเบื้องหลัง แม้ `PendingIntent.send()` ไม่เกิด exception ประวัติจึงใช้ข้อความ “ส่งคำสั่งเปิดแล้ว” ไม่อ้างว่าหน้างานเปิดสำเร็จ และสร้างแจ้งเตือน Full Lock ให้ผู้ใช้แตะเปิดเองได้ ต้องตรวจว่า Lalamove ให้ contentIntent ที่พาไปงานเฉพาะรายการจริง สิทธิ์แสดงเหนือแอปอื่นเป็นตัวเลือกเสริม ไม่รับประกันการเปิดสำเร็จ

การกันซ้ำเป็นหน่วยความจำใน service จำกัด 200 key; การรีสตาร์ต process อาจอ่านรายการเดิมอีก ต่างงานที่ Lalamove ใช้ key และข้อความเหมือนกันยังแยกจากกันไม่ได้หากไม่มีรหัสงานจริง เวลาพักเปิดซ้อนเริ่มที่การส่งคำสั่ง ไม่ใช่การยืนยันรับงาน และไม่คิวงานที่ข้ามระหว่างพัก

UI และการ build ตรวจด้วย emulator; ยังไม่ได้ยืนยันการทำงานครบวงจรกับ Lalamove Driver บนอุปกรณ์จริง

